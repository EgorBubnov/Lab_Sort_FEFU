## Задание

Реализовать два алгоритма сортировки для обработки файла с записями, каждая из которых содержит два ключа:

| Ключ | Тип | Порядок сортировки |
|------|-----|--------------------|
| Ключ 1 | Дата (`YYYY-MM-DD`) | По возрастанию |
| Ключ 2 | ФИО (`Фамилия Имя Отчество`) | По убыванию |

**Алгоритмы по варианту:**
- Пирамидальная сортировка («на месте», массив)
- Двухпутевые вставки

**Входные данные:** текстовый файл, до 1 000 000 записей вида:
```
YYYY-MM-DD\tФамилия Имя Отчество
```

**Выходные данные:** два текстовых файла с отсортированными записями (по одному на алгоритм), в последней строке каждого — время сортировки в миллисекундах. Формат строки:
```
YYYY-MM-DD\tФамилия Имя Отчество\t<номер строки в исходном файле>
```

## Реализованные алгоритмы

### Пирамидальная сортировка (Heap Sort)

Сортировка «на месте» с использованием двоичной max-кучи.

**Этапы:**
1. Построение max-heap из исходного массива за O(n).
2. Последовательное извлечение максимума в конец массива — n итераций по O(log n).

**Сложность:** O(n log n) во всех случаях  
**Дополнительная память:** O(1)  
**Устойчивость:** неустойчива

```
Heapify использует итеративный спуск, а не рекурсивный —
это исключает накладные расходы стека вызовов при больших n.
```

### Двухпутевые вставки (Two-Way Insertion Sort)

Улучшение простых вставок: элементы вставляются в двусторонний буфер, заполняемый от центра в обе стороны. Для нахождения позиции вставки применяется бинарный поиск.

**Этапы:**
1. Первый элемент помещается в центр буфера размером 2n.
2. Каждый следующий элемент: если меньше левой границы — в левую сторону, если больше правой — в правую, иначе бинарным поиском находится позиция вставки и делается сдвиг.
3. Буфер копируется обратно в массив.

**Сложность:** O(n²) в худшем случае, сравнений — O(n log n)  
**Дополнительная память:** O(n)  
**Устойчивость:** зависит от реализации; данная реализация — неустойчива

## Структуры данных

```csharp
// Дата хранится как структура из трёх int-полей, а не строка
public struct Date : IComparable<Date>
{
    public int Day, Month, Year;
}

// ФИО — три отдельных строковых поля
public struct FullName : IComparable<FullName>
{
    public string LastName, FirstName, MiddleName;
}

// Запись хранит также номер исходной строки для вывода
public class DataRecord : IComparable<DataRecord>
{
    public Date Date;
    public FullName Name;
    public int OriginalLineNumber;
}
```

Тип ключей выбран в соответствии с требованием задания: числовые данные хранятся как числа, а не строки.

## Порядок сортировки

Сравнение записей:
1. Сначала по дате — **по возрастанию** (раньше → меньше).
2. При равных датах по ФИО — **по убыванию** (лексикографически: Я → А).

```csharp
public int CompareTo(DataRecord other)
{
    int dateComparison = Date.CompareTo(other.Date);
    if (dateComparison != 0)
        return dateComparison;        // дата: возрастание

    return Name.CompareTo(other.Name); // ФИО: убывание (реализовано инверсией)
}
```

## Устойчивость

**Пирамидальная сортировка** — неустойчива. Операции `Heapify` и `Swap` при извлечении элементов из кучи нарушают исходный порядок равных элементов.

Пример:

| № строки | Дата | ФИО |
|----------|------|-----|
| 1 | 2023-01-01 | Иванов Алексей Петрович |
| 2 | 2023-01-01 | Петров Иван Сергеевич |
| 3 | 2023-01-01 | Иванов Алексей Петрович |

После пирамидальной сортировки записи 1 и 3 могут поменяться местами — порядок не сохраняется.

**Двухпутевые вставки** в данной реализации также неустойчивы: бинарный поиск может вставить равный элемент перед уже стоящим.

## Сравнение алгоритмов

| Характеристика | Пирамидальная | Двухпутевые вставки |
|----------------|:-------------:|:-------------------:|
| Лучший случай | O(n log n) | O(n log n) |
| Средний случай | O(n log n) | O(n²) |
| Худший случай | O(n log n) | O(n²) |
| Память | O(1) | O(n) |
| Устойчивость | Нет | Нет |

На больших объёмах данных пирамидальная сортировка значительно выигрывает по времени. Двухпутевые вставки эффективнее на малых массивах или данных, близких к упорядоченным, за счёт меньшего числа сравнений.

**Наихудший случай для двухпутевых вставок:** данные отсортированы в обратном порядке — каждый новый элемент вставляется в начало буфера с максимальным сдвигом.

**Для пирамидальной сортировки** все случаи (случайный, отсортированный, обратно отсортированный) дают сопоставимое время: алгоритм не имеет вырожденных входов.
